# AGENTS.md — Cinema Ticket Booking Backend

## Quick start
```bash
npm install
cp .env.example .env   # fill DATABASE_URL, JWT_SECRET, and OAuth/Cloudinary keys
npx prisma generate
npx prisma migrate dev
npm run start:dev       # http://localhost:3000
```

## Key commands
| Command | What |
|---|---|
| `npm run start:dev` | Dev server with watch |
| `npm run lint` | ESLint + Prettier (auto-fix) |
| `npm run test` | Unit tests (`*.spec.ts` in `src/`) |

## Architecture
- **NestJS 11** · TypeScript · PostgreSQL via Prisma (`@prisma/adapter-pg`)
- **API prefix**: `/api/v1` — all routes live under it
- **Swagger**: `/api-docs` — enabled only when `NODE_ENV !== 'production'`
- **No monorepo** — single `src/` with feature modules
- **Entrypoint**: `src/main.ts`
- **Global ValidationPipe**: whitelist + transform + forbidNonWhitelisted

## Modules
`src/` modules mirror DB entities: `authentication`, `movies`, `theater`, `screen`, `screen-template`, `seat-template`, `seat`, `seat-pricing`, `showtime`, `checkout`, `payment`, `file-upload`, `user`, `prisma`, `provider` (OAuth).

## Pricing model
`total = showtime.basePrice + screenTemplate.screenSurcharge + seatPricingRule.seatSurcharge`

## Cron jobs (scheduled tasks)
- **CheckoutService**: every 30s — expire stale PENDING bookings
- **SeatService**: every 30s — expire stale seat locks
- **ShowtimeService**: every 60s — update showtime statuses

## Database / Prisma quirks
- PostgreSQL provider; schema in `prisma/schema.prisma`
- Prisma client is extended in `src/prisma/prisma.service.ts` (uses `@prisma/adapter-pg`)
- Generated client lives in `node_modules`; `prisma generate` required after pulls/schema changes
- Migrations in `prisma/migrations/`

## Critical — NEVER drop the database
- **NEVER run `prisma migrate reset` or `prisma db push --accept-data-loss` without explicit user approval.**
- If a migration requires a reset, ask the user first and explain the alternatives.
- If the database has drift from migration history, use `prisma migrate diff` to inspect first, then ask the user how to proceed.
- Prefer `prisma migrate dev --create-only` to generate migration files without applying them when there's drift.

## WebSocket / real-time
- **Namespace**: `/seats` — Socket.IO gateway in `src/seat/seat.gateway.ts`
- **Auth**: JWT via handshake `auth.token` or `query.token` (optional — unauthenticated connections allowed for seat viewing)
- **Rooms**: `showtime:<showtimeId>` — clients join via `joinShowtime` / `leaveShowtime`
- **Server events**:
  | Event | Payload | When |
  |---|---|---|
  | `seat:locked` | `{ seatId, showtimeId }` | Seat lock created |
  | `seat:unlocked` | `{ seatId, showtimeId }` | Seat unlocked or lock expired |
  | `seat:booked` | `{ seatIds[], showtimeId }` | Booking confirmed (payment success) |
  | `seat:expired` | `{ seatIds[], showtimeId }` | PENDING booking expired |
- **Emitter services**: `SeatService`, `CheckoutService`, `PaymentService` all inject `SeatGateway`

## Auth & security
- JWT (15m access) + refresh tokens via Passport strategies
- OAuth: Google, GitHub, Facebook, Discord
- 2FA: TOTP, SMS, Email (via speakeasy + qrcode)
- Custom throttler guard in auth module
- Helmet + cookie-parser in bootstrap

## Style / config
- Prettier: `singleQuote: true`, `trailingComma: "all"`
- ESLint: `no-floating-promises: warn`, `no-unsafe-argument: warn`
- **Never use `any`** — prefer `unknown` for truly unknown types; create interfaces/types; use generics where appropriate
- Target strict TypeScript compatibility in all new code
- CORS allows `localhost:3000-3002` with credentials

## Test conventions
- Unit tests: `*.spec.ts` co-located in `src/` next to source files
- E2E tests: `test/*.e2e-spec.ts` with separate jest config `test/jest-e2e.json`
- `jest.config` is embedded in `package.json` (rootDir: `src`)
- `supertest` available for HTTP assertions

## Generated / ignored
- `.env` (gitignored) — must exist with `DATABASE_URL`, `JWT_SECRET`, Cloudinary/OAuth keys
- `/dist` (build output), `/coverage`, `/generated/prisma` all gitignored
- `prisma.config.ts` is auto-generated by Prisma CLI — do not edit manually
